# UI 전체 개편 설계

## 목적과 적용 상태

최우선 목표는 개발자가 UI 코드와 Unity 계층을 이해하고 직접 수정할 수 있는 일관된 구조를 만드는 것이다. Intro·공방·총기 에디터·습격·튜토리얼·엔딩을 포함한 전체 UI를 MVP로 개편한다. 일부 화면만 개선하고 끝내는 작업이 아니다.

이 문서는 대화에서 합의한 설계와 후속 작업 기준이다. 새 구조의 구현·씬 연결·기능 보존 점검을 완료했다는 뜻이 아니다. 기존 게임 기능과 조작은 보존하며, 명시적으로 합의한 동작 변경만 적용한다.

**총기 에디터·대사 입력과 관련 정책을 정적으로 재조사했다. 보존할 기능과 동작 차이는 [UIRefactorDifferences.md](UIRefactorDifferences.md)에 정리했다. D01~D09는 모두 확정됐으며 적용 단위와 남은 범위는 [현황](UIRefactorP0/Overview.md)을 따른다.**

최초 조사 기준은 develop `62f7a9a`, 현재 브랜치는 feature/bs_patch(HEAD `91122f5`)이며 사용자 변경을 보존한다. 2D Ctrl+휠 층 이동·연속 삭제와 Main UI 오버라이드를 대조하고 확정 정책에 해당하는 항목만 바꾼다. P0 목록·[공통 계약](UIRefactorP0/Contracts.md), 공용 레이어·Pause·확인창·날짜 전환·결과·대화와 [메뉴·설정·편집 표시](UIRefactorP0/P2ParallelWaveImplementation.md)의 MVP 단위를 반영했다. Dialogue의 루트 직계 예외는 제거하고 ScreenLayer로 연결했다. 전체 이관과 플레이 보존 확인은 미완료이며 현재 범위는 [현황](UIRefactorP0/Overview.md)을 따른다.

## 확정된 구조

### MVP 역할

| 구성 | 책임 | 두지 않을 책임 |
| --- | --- | --- |
| Model | 실제 게임 상태·규칙·데이터와 변경 알림 | 화면 배치·포커스·표시 처리 |
| View | UI 참조, 표시, Unity UI 입력을 C# 이벤트로 전달 | 날짜 진행·결제·보상 계산, Model·다른 화면 직접 참조 |
| Presenter | Model과 View 연결, 표시 데이터 가공, 사용자 요청 처리 | RectTransform 배치·색상·UI 계층 생성, UI 컴포넌트 직접 조작 |
| 흐름 담당자 | 화면 간 이동, 중첩, 입력 정책, 포커스 저장·복원 | 경제·보상 등 게임 규칙의 중복 구현 |

- 의미 있는 화면 단위로 View와 Presenter를 한 쌍씩 둔다. 단순 버튼·텍스트·표시 행마다 Presenter를 만들지 않는다.
- View는 프리팹·씬에 붙는 MonoBehaviour, Presenter는 일반 C# 클래스를 기본으로 한다.
- 지정된 초기화 지점에서 Model과 View를 Presenter에 명시적으로 전달한다. 이름 기반 연결과 자동 탐색 폴백을 줄인다.
- Presenter는 구체적인 View를 명시적으로 받는 것을 기본으로 한다.
- 작은 인터페이스와 필요한 공통 기능만 사용한다. 제네릭 기반 다단계 상속과 전역 이벤트 버스는 도입하지 않는다.
- 공방·습격 등 영역별 흐름을 나누고, 공통 화면 상태·입력 정책은 한곳에서 적용한다. 모든 진행을 거대한 단일 흐름 클래스에 모으지 않는다.
- 화면 식별에는 명시적 참조와 필요한 enum을 사용한다. 문자열·오브젝트 이름으로 런타임 판별하지 않는다.
- 기존 PlayerWallet·날짜·습격 등의 기능을 Model 측에서 활용한다. 화면별로 실제 데이터를 복제하거나 기존 Model 전체를 불필요하게 재작성하지 않는다.
- 작업대 모드와 장착 상태는 플레이어 컴포넌트가 소유한다. Interaction은 공통 시선·입력·상호작용 전달 역할을 유지한다.

### 이벤트와 표시 갱신

- View → Presenter는 `event System.Action` 또는 `event System.Action<T>`를 기본으로 한다. 이벤트 발생은 `?.Invoke()`를 사용한다.
- Presenter → View는 `Show()`, `SetSummary(...)` 같은 명시적 함수 호출을 사용한다.
- Unity Button.onClick은 View 내부에서 받아 C# 이벤트로 전달한다. Inspector OnClick 연결과 코드 연결을 혼용하지 않는다.
- 구독·해제는 이름 있는 함수로 작성한다. 해제가 필요한 익명 람다는 피한다.
- Presenter 연결·해제는 `Initialize()`와 `Dispose()`로 통일한다.
- Model 변경 알림도 Action 계열을 사용한다. 상태 변경 이벤트로 표시를 갱신하고, 조준점·게이지 등 연속 갱신 요소만 별도로 처리한다.

```csharp
public event Action ConfirmRequested;
public event Action<int> SlotSelected;

private void OnConfirmClicked()
{
    ConfirmRequested?.Invoke();
}

private void OnSlotClicked(int _slotIndex)
{
    SlotSelected?.Invoke(_slotIndex);
}
```

### 코드 스타일

| 항목 | 규칙 |
| --- | --- |
| 정렬 | 사용자가 지정한 Visual Studio Ctrl+K, R 기준. 단축키에 대응하는 실제 설정을 확인한 뒤 도구 설정에 반영 |
| 중괄호 | BSD 방식으로 여는 중괄호를 다음 줄에 배치 |
| 코드 블록 | 한 줄로 압축하는 블록을 지양하고 여러 줄로 작성 |
| 클래스·함수 | 대문자로 시작하는 PascalCase: TableData, GetData |
| 지역 변수 | 소문자로 시작하는 camelCase: canvasPanel, count |
| 파라미터 | 반드시 `_` 접두사: _canvasPanel, _count |
| 멤버 변수 | 가급적 `m_` 접두사: m_canvasPanel, m_count |
| const·static 변수 | 반드시 대문자: MAX_LENGTH, MAX_WIDTH |
| 이름이 길거나 읽기 어려울 때 | snake_case 허용 |

Unity 콜백 등 정해진 이름은 유지한다. 외부 패키지·자동 생성 코드를 일괄 스타일 변경 대상으로 삼지 않는다.

## 프리팹과 폴더

화면별 프리팹과 코드 폴더를 대응시킨다. 예를 들어 정산 수정은 SettlementScreen 프리팹과 Settlement 폴더부터 보면 되는 구조로 만든다.

```text
UIRoot
├─ HudLayer
├─ ScreenLayer
├─ PopupLayer
└─ TransitionLayer

SettlementScreen.prefab
├─ SettlementView
├─ SummaryPanel
├─ ConfirmButton
└─ NextDayButton

UI/
├─ Settlement/
│  ├─ SettlementView.cs
│  └─ SettlementPresenter.cs
├─ Pause/
├─ RaidMap/
└─ Common/
```

- 화면 프리팹 루트에 해당 View를 붙인다. 버튼·텍스트·패널·기본 포커스·Navigation 경로는 Inspector에서 명시적으로 연결한다.
- UIRoot의 초기화 지점에서 화면과 Presenter를 연결한다. 위 트리는 역할 기준이며 실제 파일·계층 이름은 P0에서 확정한다.
- 단순 행 View는 표시와 선택 이벤트 전달을 담당하고 화면 Presenter가 목록을 관리한다.

## 레이아웃과 표시 순서

| 항목 | 확정 기준 |
| --- | --- |
| 기준 해상도 | 1920×1080 |
| 지원 범위 | 16:9·21:9와 더 높은 해상도. 4:3은 제외 |
| 크기 대응 | CanvasScaler의 Scale With Screen Size 사용 |
| 화면비 대응 | 배경은 전체 화면, 주요 조작 UI는 중앙 최대 너비 영역 사용 |
| 21:9 | 콘텐츠를 무작정 늘리지 않고 배경·게임 화면 영역 확장 |
| HUD | 화면 가장자리 기준 Anchor와 공통 여백 사용 |
| 팝업 | 중앙 정렬·최대 크기 제한. 긴 내용은 본문만 스크롤 |
| 작업대 | 좌우 UI를 제외한 실제 작업 영역을 기준으로 무기·카메라 중심 계산 |
| 간격 | 8 단위, 기본 간격 16·패널 내부 여백 24를 출발점으로 적용·조정 |
| 정렬 | 화면 틀은 Anchor와 프리팹 배치, 반복 요소는 Layout Group 사용 |
| 제어 충돌 방지 | 같은 RectTransform의 위치·크기를 수동 배치·코드·자동 레이아웃이 동시에 제어하지 않음 |

- 그리기 순서, 부모·자식 소속, 입력 우선순위를 구분한다.
- 표시 순서는 HUD → 기능 화면 → 팝업 → 전환 연출로 고정한다.
- 같은 Layer 안에서는 Hierarchy 순서를 기본으로 한다. 별도 Canvas 정렬값은 필요한 경우에만 사용한다.
- 같은 계층의 순서는 흐름 담당자만 변경한다. 개별 화면이 임의로 앞으로 나오지 않는다.
- 공통 버튼·팝업·행은 공통 프리팹으로 관리한다.

## 화면 중첩과 입력

### 공통 원칙

- 기본 기능 화면은 하나만 열고, 그 위에 공용 팝업을 표시할 수 있다. HUD는 별도 관리한다. D03의 대화 → 일시정지 → 이탈 확인과 튜토리얼 Suspend 중첩은 명시적 예외이며 아래 화면·포커스를 보관한다.
- 팝업은 기본 한 개만 허용한다. 겹친 요청은 흐름 담당자가 아래 충돌 처리 규칙에 따라 처리한다. D03과 튜토리얼의 의도된 중첩에는 해당 예외를 적용한다.
- 위 화면이 열리면 아래 화면의 클릭·방향키 입력을 막는다.
- 팝업을 닫아도 아래 화면에 필요한 입력 차단은 유지한다.
- 배경 클릭으로 창을 닫지 않는다. 닫기 버튼·ESC를 사용한다. D04의 대사·단일 안내는 전체 화면 클릭을 확인 입력으로 받는 예외이며, 일반 Yes/No에는 적용하지 않는다. 단일 안내 ESC는 취소다.
- 흐름 담당자가 게임 조작 차단·시간 정지·커서·ESC 정책을 적용한다. View와 Presenter는 커서와 Time.timeScale을 직접 변경하지 않는다.
- UI 연출은 실제 시간 기준으로 동작해 게임 시간이 멈춰도 유지된다.
- 연결·초기화 후 필요한 HUD만 표시한다. 기능 화면·팝업은 씬 저장 상태에 의존하지 않고 명시적으로 숨긴다.
- 모든 조작은 Assets/InputSystem_Actions.inputactions의 새 Input System 액션을 사용한다. 기존 입력을 보존하며 직접 키·마우스 폴링이나 코드 전용 바인딩을 추가하지 않는다.

### 팝업 요청 충돌

| 상황 | 확정 처리 |
| --- | --- |
| 같은 팝업 중복 요청 | 기존 팝업 유지, 중복 요청 무시 |
| 다른 일반 팝업 요청 | 자동 대기열에 넣지 않고 요청 거부 결과 반환 |
| 사망·게임오버·씬 이동 | 흐름 담당자가 기존 팝업 강제 종료 후 필수 흐름 진행 |
| 요청 대상 무기·항목 소멸 | 팝업 종료, 확인 동작 실행하지 않음 |
| 짧은 알림 중복 | 최신 문구로 교체 |
| 튜토리얼의 의도된 중첩 | 명시적 예외로 관리하고 기존 행동·입력 제한 보존 |

- 요청자는 표시 성공 여부를 받는다. 표시되지 않은 팝업의 확인을 기다리는 상태로 남지 않는다.
- 강제 종료는 사용자 취소와 구분한다. 강제 종료로 결제·저장·화면 이동 같은 후속 동작을 실행하지 않는다.
- 일반 팝업을 자동 대기시키지 않는다. 과거 요청이 대상·잔액 변경 이후 뒤늦게 표시되지 않게 한다.

### 화면별 정책

| 화면·상태 | 게임 조작 | 시간 | 커서 | ESC |
| --- | --- | --- | --- | --- |
| 일반 플레이·HUD | 허용 | 진행 | 숨김 | 일시정지 열기 |
| 작업대 편집 | 이동·사격 차단, 편집 허용 | 진행 | 표시 | 드래그 취소 → Tab 목록 닫기 → 작업대 퇴장. 한 입력에 한 단계 |
| 일시정지 | 차단 | 정지 | 표시 | 계속하기 |
| 일시정지의 설정·저장 | 차단 | 정지 | 표시 | 일시정지 메뉴로 |
| 정산창 | 차단 | 정지 | 표시 | 무시. 확인 버튼·F로만 닫기. 파산 정산도 동일 |
| 습격 지도 | 차단 | 정지 | 표시 | 뒤로 버튼과 같은 지도 닫기 |
| 무기 이름·공유·프리셋·레시피 | 월드·편집 조작 차단 | 진행 | 표시 | 입력 취소 또는 창 닫기 |
| 공용 확인창 | 아래 화면 조작 차단 | 아래 화면 정책 유지 | 표시 | 취소 |
| 대화 | 이동·사격·상호작용 차단 | 기존 동작 보존, 종류별 최신 코드 대조 | 표시 | 일시정지 열기(D03), Suspend된 선택창은 소비 |
| 결과창·엔딩 선택 | 차단 | 아래 시간 정책 적용, 기존 연출과 충돌 시 별도 결정 | 표시 | 기본 무시 |
| 씬 이동·전환 연출 | 차단 | 전환별 지정 필요 | 숨김 | 무시 |

튜토리얼의 행동·대상 제한 같은 예외는 기존 규칙을 보존하고 화면 정책에 이유를 명시한다. 지도 ESC 닫기와 정산 ESC 무시는 합의된 정책으로 기록하며 기존 동작과 구분한다.

### 방향키와 포커스

- 새 Input System UI 액션과 EventSystem·Selectable Navigation을 사용한다.
- 흐름 담당자는 입력 대상 화면과 화면 전환 시 포커스 저장·복원을 담당한다.
- Presenter는 최초 선택 항목과 선택 항목 소멸·비활성 시 대체 항목을 결정한다.
- View는 실제 선택을 적용하며 이동 경로는 가급적 Inspector에서 명시적으로 연결한다.
- 화면을 열면 기본 버튼을 선택한다. 삭제·이탈 확인창은 취소 버튼을 기본 선택한다.
- 방향키는 가장 위 화면 안에서만 이동한다. 숨김·사용 불가 항목은 제외한다.
- 키를 유지하면 지연 후 반복 이동한다. 끝에서 반대편으로 순환하지 않는다. 지연·반복 수치는 P0에서 정한다.
- 스크롤 밖 항목을 선택하면 해당 항목이 보이도록 이동한다.
- 마우스 호버와 선택 포커스를 구분한다. 호버로 포커스를 강제 변경하지 않고 클릭 시 해당 항목을 선택한다.
- 팝업을 닫으면 이전 선택으로 복귀한다. 화면 재열기는 기본 선택과 임시 입력을 초기화하되 화면별 기존 보존 기능과 대조한다.
- 텍스트 입력 중 방향키는 글 편집에 사용한다. Enter는 해당 입력 확정에만 사용하고 뒤 버튼으로 중복 전달하지 않는다. ESC는 입력 취소 후 이전 포커스로 복귀한다.

## 전환과 생명주기

### 초기화와 구독 수명

| 시점 | 확정 처리 |
| --- | --- |
| 씬 초기화 | Model 준비 → View 참조 확인·숨김 초기화 → Presenter 생성·연결 |
| Initialize | 버튼 등 View 이벤트 구독. 화면을 열 때마다 반복하지 않음 |
| 화면 열기 | 최신 데이터 조회 → Model 변경 알림 구독 → 표시 갱신 → 화면·포커스 적용 |
| 화면 닫기 | 입력 차단 → 표시 갱신 구독 해제 → 숨김·임시 상태 정리 |
| Dispose | 남은 구독·자원 해제. 여러 번 호출돼도 문제없게 작성 |
| 씬 종료 | 흐름 담당자가 화면 강제 종료 후 Presenter 정리 |

- 연결 수명과 화면 표시 수명을 구분한다. 버튼 이벤트는 처음 연결하고 마지막에 해제하며, 표시 갱신용 Model 이벤트는 열린 동안만 구독한다.
- Awake에서는 View 자체의 시작 상태만 초기화한다. 다른 매니저를 찾아 연결하지 않는다.
- 필수 Inspector 참조가 빠지면 화면명과 누락 필드를 명확히 알리고 해당 화면 초기화를 중단한다.
- 씬에 필요 없는 화면은 구성에서 명시적으로 제외한다. 참조 누락을 자동으로 선택 기능이라고 추정하지 않는다.
- Presenter 준비 전에는 버튼 입력을 허용하지 않는다.
- 화면 닫기와 Presenter 폐기를 구분해 재열기를 지원한다.
- 지연 처리 결과는 요청 당시 화면·대상이 여전히 유효할 때만 반영한다.

### 대화와 결과 및 엔딩의 시간 정책

- 대화는 기존 동작을 보존한다. 종류별 적 행동·영업 타이머 등의 진행 여부를 최신 코드에서 확인해 명시한다.
- 습격 생존·사망 결과가 확정되면 전투와 탈출·보상 집계를 종료한다. 결과창 애니메이션은 실제 시간으로 재생한다.
- 게임오버 결과에서는 게임 진행을 멈추고 결과 확인과 메뉴 복귀만 허용한다.
- 엔딩은 기존 카메라·적 정지·연출 순서를 보존한다. UI 구조 개편을 이유로 연출 타이밍을 변경하지 않는다.
- 화면이 열렸다는 이유만으로 일괄 Time.timeScale = 0을 적용하지 않는다. 게임 진행 중단과 UI 애니메이션을 구분한다.
- D07의 탈출 결과 고정 등 명시적으로 합의한 변경은 적용한다. 그 밖의 최신 구현 충돌은 차이를 별도로 보고하고 사용자 결정 전까지 기존 동작을 유지한다.

### 전환 실패 복구

| 상황 | 확정 처리 |
| --- | --- |
| 새 화면 초기화·표시 실패 | 기존 화면이 유효하면 다시 표시하고 입력·포커스 복원 |
| 결제·저장 등 실제 처리 실패 | 성공 화면으로 넘어가지 않고 실패 이유 안내 |
| 실제 처리 성공 후 화면 표시 실패 | 실제 처리를 재실행하지 않고 최신 Model 상태로 화면 복구 |
| 기존 화면 복구 불가 | 해당 상황의 명시적 복구 경로 사용. 임의로 Main·Intro로 이동하지 않음 |

- 화면 표시 성공 여부와 실제 게임 처리 성공 여부를 구분한다. UI 실패를 이유로 중복 결제하거나 이미 지급된 보상을 임의 취소하지 않는다.
- 실패 후 재시도는 사용자의 명시적 요청에 따라 수행하며 이전 요청의 완료 여부를 먼저 확인한다.
- 복구 시 입력·포커스 정책도 함께 복원해 중복 입력 차단 잔존과 커서 잠김을 방지한다.

### 전환 실행

- Presenter는 전환을 요청하고 흐름 담당자만 실제 화면을 열고 닫는다.
- 전환 중 추가 클릭·확인·ESC를 차단한다. 처리 중 버튼 비활성화와 요청 중복 차단을 함께 적용한다.
- 전환은 기존 화면 입력 차단 → 닫기 → 새 화면 데이터 갱신 → 표시 → 포커스 설정 순서로 한다.
- 팝업 취소 버튼과 ESC는 같은 취소 경로를 사용한다.
- 확인 종료·취소 종료·강제 종료를 구분한다. 사망·씬 이동으로 강제 종료할 때 일반 확인이나 취소 동작을 임의 실행하지 않는다.
- 씬 이동 시 열린 화면·팝업·선택 상태를 정리하고 새 씬에서 명시적으로 초기화한다.
- 비동기 결과가 늦게 도착해도 닫힌 화면을 다시 열거나 갱신하지 않는다.
- 화면을 열 때 최신 Model 상태로 전체 갱신하고, 열린 동안 변경 이벤트를 구독한다. 닫히면 표시 갱신 구독을 해제한다.
- 기본적으로 씬에서 한 번 연결하고 열기·닫기로 재사용한다. Presenter의 연결 수명과 화면 표시 구독 수명을 구분한다.
- 짧은 안내는 알림, 사용자 확인이 필요한 실패는 확인창을 사용한다.
- 화면별 빈 상태·사용 불가·처리 중·실패 상태를 명시한다.

## UI 생성과 데이터

### 동적 생성 허용 범위

| 대상 | 구성 방식 |
| --- | --- |
| 메뉴·정산·지도·설정·팝업 | 전체 화면 구조를 프리팹에서 편집 |
| 즐겨찾기·저장 슬롯 등 고정 항목 | 슬롯을 프리팹에 미리 배치 |
| 모듈·재질·스티커·키링 목록 | 목록 영역은 미리 배치하고 항목 프리팹만 반복 생성 |
| 주문 태그·습격 보상 목록 | 배지·행 프리팹을 필요한 만큼 표시 |
| 알림·게이지·귀환 검정 화면 | 전용 프리팹 사용 |
| 컬러 선택기 | 조작 요소는 프리팹, 색상 텍스처 계산만 코드 |

- new GameObject·AddComponent로 UI 계층을 조립하지 않는다.
- 반복 항목 배치는 Layout Group과 항목 프리팹에서 관리한다.
- 항목 선택은 배열 순번 대신 데이터 ID를 전달한다. 정렬은 명시적 정렬 값을 사용하며 ID 자체에 순서 의미를 두지 않는다.
- 빈 목록에는 안내를 표시한다. 갱신 후 같은 ID가 남으면 포커스를 유지한다.
- 선택 항목이 사라지면 가까운 사용 가능 항목, 항목이 없으면 닫기·뒤로 버튼으로 이동한다.
- 화면을 열 때마다 전체 항목을 파괴·재생성하지 않고 재사용한다. 범용 풀링 시스템은 필요성이 있을 때 검토한다.

### 테이블 경계

- 반복 데이터와 기획 조절값을 테이블화한다. 모듈·지역·보상·비용·반복 안내·튜토리얼 단계 등이 후보이며 실제 이관 목록은 P0에서 확정한다.
- JSON → 직렬화 데이터 클래스 → TableManager 방식을 따른다. 필요한 인스턴스는 TableManager에서 받는다.
- 데이터 클래스에는 계산·판정을 넣지 않는다. 로직은 별도 클래스·매니저가 담당한다.
- UI 계층·배치·폰트·색상·오브젝트 참조는 씬·프리팹에 둔다. 열림·포커스 같은 임시 UI 상태는 테이블화하지 않는다.
- 같은 값을 표·씬·코드에 이중 저장하지 않는다. 키는 배열 위치가 아닌 순서 무관 식별자다.
- 이번에 건드리는 레거시 테이블은 AGENTS.md의 이관·Obsolete·경고 유지 규칙을 따른다.

## 기능 보존과 누락 방지

총기 에디터에서 드래그로 슬롯을 변경하는 기능은 반드시 유지한다. UI 목록과 별도로 전체 기능·조작 보존 목록을 P0에서 작성한다. 아래 표는 조사 범주이며 아직 모든 기존 동작을 확인한 명세가 아니다.

| 조사 범주 | 반드시 대조할 내용 |
| --- | --- |
| 드래그 | 목록→슬롯, 슬롯 이동·교환, 잘못된 드롭, 취소, 화면 종료 |
| 입력 | 좌우 클릭, 단축키, 길게 누르기, 휠, 방향키 선택·확인 |
| 입력 충돌 | UI와 사격·배치 동시 실행, F 중복 진행, 입력칸과 단축키 충돌 |
| 작업대 | 진입·퇴장, 무기 전환, 제작·커스텀, 2D·3D, 카메라 복원 |
| 선택 상태 | 슬롯·재질·페이지·스크롤·포커스의 유지와 초기화 |
| 편집 | Undo, 삭제, 도색·스티커·키링, 프리셋, 이름, 공유 코드 |
| 경제·저장 | 결제·환불, 부족 안내, 중복 지급, 자동저장 시점과 호환 |
| 중첩·중단 | 팝업 취소·복귀, 입력 차단 유지, 사망·씬 이동 |
| 튜토리얼 | 허용 행동·대상, 강조, 완료 신호, 연습 경제·장면 복원 |
| 표시·연출 | 호버, 잠금·선택, 숫자·효과음·게이지, HUD 숨김·복원 |

각 기능은 다음 정보를 가진다.

```text
기능 ID / 기능명
기존 코드·프리팹·씬 근거와 기준 커밋
사용 조건·입력
정상 결과
취소·실패·중단 처리
새 구현 담당 작업
구현·씬 연결 상태
사용자 플레이 확인 상태
합의된 동작 변경 또는 미결정 차이
```

- 정상 동작과 취소·실패·중단 경로를 함께 조사한다. 추정 동작을 기존 사실로 적지 않는다.
- 모든 기존 기능을 담당 작업에 배정한다. 작업자는 이전 기능과 새 구현의 대응 관계를 제출한다.
- 관리자는 코드·직렬화 연결을 대조하고, 이전 코드에만 남은 기능이 없는지 확인한 뒤 제거한다.
- 기존 동작이 이상해도 임의 수정하지 않는다. 합의된 변경은 기능 누락과 구분해 기록한다.
- 코드상 확인·씬 연결 확인·사용자 플레이 확인을 분리한다. 테스트·플레이·검증 실험은 사용자가 요청할 때만 실행한다.

## 작업 분할과 우선순위

실제 구현은 orca-orchestration을 사용한다. 관리자는 현재 세션이며 작업 배정·계약 조율·결과 검토·통합을 담당한다. 작업자 설정은 이 프로젝트의 .orca/orchestration-profile.json을 기준으로 확인하고, 현재 세션 관리자라는 사용자 지시를 우선한다.

- High 작업자는 `qoder / DeepSeek-Flash`를 사용한다. Argon은 P1-A 첫 제출 주기로 종료했으며 후속 배정부터 새 설정을 적용한다. 관리자는 현재 세션을 유지한다.
- 현재 Orca의 Qoder 실행은 launch-time 모델 지정을 지원하지 않아 프로젝트 `.qoder/settings.local.json`의 `model.name`으로 선택한다. 실제 후속 워커 화면에서 `DeepSeek-Flash Model`을 확인했다. 다른 모델로 임의 대체하지 않는다.

| ID | 단계 | 작업 단위 | 의존·산출 |
| --- | --- | --- | --- |
| P0-A | 선행 | 최신 기준과 전체 UI·기능 목록 | 저장소 최신화, 기준 커밋 기록, 총기 에디터 별도 재조사, 기능 보존 목록·소유권 |

P0 → P1 → P2의 독립 영역 병렬 진행 → P3 순서다. 기반 계약이 정해지기 전에 영역별 임의 공통 구조를 만들지 않는다. 작업대·커스텀·튜토리얼처럼 결합된 영역은 연결 계약을 먼저 맞춘다. 최종 범위는 전체 UI이며 첫 화면만 완성하고 종료하지 않는다.

### 작업자 수정 권한

- 영역 작업자는 자기 화면의 코드와 전용 프리팹만 담당한다.
- 공통 기반은 지정 작업자만 수정한다.
- 공용 프리팹·씬은 통합 담당자만 수정한다. 같은 씬·공용 프리팹을 여러 작업자가 동시에 편집하지 않는다.
- 다른 영역 변경이 필요하면 관리자에게 요청하고 담당자를 지정한다.
- 각 작업자는 수정 파일·제거 대상·필요한 씬 연결·기능 대응·남은 결정을 함께 전달한다.
- 수정한 Assets만 AssetDatabase.ImportAsset으로 해당 작업에서 한 번 임포트한다. 목록을 조율해 같은 자산을 중복 임포트하지 않으며 전체 Refresh·Reimport는 필요한 경우에만 사용한다.
- 완료는 구현과 실제 씬 연결까지다. 새 View·Presenter만 작성하고 이전 UI가 계속 동작하는 상태는 완료가 아니다. 플레이 미확인은 별도로 남긴다.
- 기존 외형·게임 규칙을 유지하며 구조를 개편한다. 합의된 화면비 대응·레이아웃·입력 정책과 D05~D07 게임 동작 변경은 명시적으로 반영한다.

## 최신화 후 총기 에디터 재확인

최신화와 지정 에디터·관련 UI의 정적 재조사는 완료했으며 결과는 [UIRefactorDifferences.md](UIRefactorDifferences.md)에 있다. 아래는 전체 기능 목록·후속 구현으로 연결하기 위한 절차이며, 전체 P0 조사나 플레이 확인 완료를 뜻하지 않는다.

1. 사용자 변경을 보존하며 저장소 최신화를 수행하고 기준 커밋을 기록한다. 분기 충돌 등으로 판단이 필요하면 그 지점에서 확인한다.
2. 변경된 에디터 코드뿐 아니라 연결 프리팹·씬·입력 액션·튜토리얼 참조를 함께 대조한다.
3. 모듈 선택·즐겨찾기·슬롯 드래그·교환·취소, UI와 3D 조작 충돌, 단축키·휠·회전·2D·3D, 커스텀·Undo를 기능 보존 목록에 반영한다.
4. 합의된 설계와 최신 동작의 차이를 정리하고, 확정된 D01~D09 외에 새로 발견한 동작 충돌을 따로 보고한다.
5. 기준이 확정된 뒤 P2-C·P2-D에 작업을 배정한다. 이 과정에서 요청 없는 플레이·검증 실험을 실행하지 않는다.

### 총기 에디터 입력 이관 기준

최신화·재조사 후 D01~D09는 모두 확정됐다. 아래 입력 점유·취소·View 이벤트 연결은 기존 기능 및 공통 입력 원칙과 대조해 P0 대응표에 구체화한다. 추가 게임 동작 충돌을 발견하면 별도로 보고한다.

- UI 위 클릭·휠은 해당 UI가 처리하고 무기 배치·사격·카메라 조작으로 전달하지 않는다.
- 확정된 D02: 슬롯 드래그 중 무기 회전·팬·줌을 차단한다. UI 밖에서도 슬롯 드래그를 유지하고 바깥 드롭은 취소한다. 2D 배치의 UI 진입·뷰포트 이탈 취소와 UI 밖에서 시작한 3D 회전의 유지 규칙은 각각 보존한다. UI 위에서 새 회전은 시작하지 않는다.
- 확정된 D01: 슬롯 드래그·2D 연속 배치·연속 삭제 중 ESC는 드래그만 취소한다. 드래그가 없으면 Tab 목록 닫기, 그다음 작업대 퇴장 순서로 한 입력에 한 단계만 처리한다.
- 드래그 중 화면 종료·앱 포커스 상실 시 취소와 입력 점유 해제를 수행한다.
- Unity 드래그 인터페이스를 View에서 받고 Action 이벤트로 전달하며, Presenter가 상태·대상을 관리하고 공통 입력 정책이 중복 조작을 차단한다.

슬롯 드래그 기능 보존과 유효한 드롭 시 변경 확정이라는 상위 합의는 유지하되, 세부 조작은 최신 구현과 대조한다.

## 추가 확정 정책과 P0 위임

- 기존 디자인·문구·효과음은 보존하면서 구조·정렬·화면비 대응을 개편한다. 별도 시각 디자인 변경은 분리한다.
- 기존 세이브·즐겨찾기·프리셋·설정값을 유지한다. UI 개편 때문에 저장 형식을 불필요하게 변경하지 않는다.
- 필드명·컴포넌트·프리팹 변경 시 Inspector 직렬화 참조를 같은 작업에서 이관한다.
- 기존 폰트·색상·선택 테두리를 기준으로 공통 버튼·팝업·행을 제작한다.
- 역할이 드러나는 오브젝트 이름을 사용하고, 구분선용 빈 오브젝트·의미 없는 숫자 이름은 제거한다.
- 씬 오버라이드는 외부 참조와 의도된 차이만 유지한다. 공통 외형은 공용 프리팹에서 관리한다.
- 에디터 도구 실행 시점을 명시하고 수동 편집을 임의로 덮어쓰지 않는다. 최종 UI 편집이 생성 도구에 종속되지 않게 한다.
- 여러 표시값이 함께 바뀌는 화면만 작은 표시 데이터 클래스로 묶는다. 단일 텍스트 갱신까지 클래스로 만들지 않는다.
- 오류는 화면·요청·이유를 구분해 기록하고 같은 오류를 매 프레임 반복 출력하지 않는다.
- 현재 비활성 기능은 비활성 상태를 보존한다. 명시적으로 수락한 D09 층 이동 버튼 재표시는 예외다. 그 외 기능을 개편을 이유로 재활성화하거나 임의 삭제하지 않는다.
- 명시적 합의 변경 → 최신 구현에서 확인한 기존 동작 → 미결정 사항 순서로 판단한다. 충돌은 보고 후 결정한다.
- UI 연결과 명시적으로 확정한 D05~D07 정책에 필요한 게임 코드 수정을 포함한다. 그 밖의 경제·전투·진행 규칙 개선은 별도 작업으로 분리한다.

### 최신 구현 대조 후 확정한 정책

D01·D02 입력 정책과 함께 아래 D03~D09를 모두 수락했다. 상세 현재 동작·근거·차이는 [UIRefactorDifferences.md](UIRefactorDifferences.md)를 따른다.

| 항목 | 확정 정책 |
| --- | --- |
| D03 대화와 일시정지 | 대화 중 ESC로 일시정지를 열고, 닫으면 기존 대화·포커스로 복귀한다. 일시정지의 이탈 확인창까지 중첩을 허용하며 최상위만 입력을 받는다. Suspend된 선택창의 ESC 소비는 유지한다. |
| D04 단일 안내 | 전체 화면 클릭 확인과 ESC 취소를 유지한다. 일반 Yes/No는 범용 클릭 진행에서 제외한다. |
| D05 다음 날 스킵 | 정산창·셔터 양쪽 모두 부품 100 지급과 날짜 페이드·Day 제목을 적용한다. 습격 귀환·튜토리얼 진행과 구별해 중복 지급을 막는다. |
| D06 연속 배치 비용 부족 | 경로를 취소하고 단일 설치와 같은 조건에서 대출을 안내한다. 승인 후 사용자가 다시 배치하며 자동 설치하지 않는다. |
| D07 탈출 결과 | 탈출 5초 완료 시 생존 성공·예정 보상을 고정한다. 이미 사망한 경우 사망 우선이며 실제 지급·저장은 기존 복귀 확인 절차에서 한 번만 수행한다. |
| D08 튜토리얼 선획득 | 이번 습격의 티켓·부품 누적 획득을 인정한다. 안내 후 새 획득은 강제하지 않는다. |
| D09 층 이동 | Ctrl+휠과 기존 층 이동 버튼을 병행한다. 버튼을 다시 표시해 마우스·방향키 선택을 지원한다. |

### 화면 재표시 상태

- 게임에 저장된 선택·설정은 Model에서 복원한다.
- 미확정 이름·코드 같은 임시 입력은 기본 초기화한다.
- 잠시 가렸다가 돌아온 화면은 목록 페이지·스크롤·선택 위치를 유지한다.
- 화면 완전 종료 후 재진입의 유지 여부는 기존 기능과 대조해 화면별로 명시한다.
- Hide 호출만으로 즐겨찾기·실제 편집 결과를 초기화하지 않는다.

### P0 담당자에게 위임한 구현 세부사항

- 정확한 클래스·함수·enum·요청 결과 형식, 화면 분할·프리팹 구성·파일 소유권.
- 테이블 이관 목록과 데이터 ID·정렬 필드, 여러 값을 묶는 표시 데이터 형식.
- 최대 콘텐츠 너비·폰트 크기·키 반복 간격·연출 시간.
- Visual Studio 정렬 기준을 재현하는 포맷 설정.
- 전체 기능 보존 목록과 기존 기능에서 새 구현으로의 대응표.
- 합의 원칙 안의 구현 선택은 관리자가 조율하고 매번 사용자 확인을 받지 않는다. 게임 동작 충돌은 별도로 결정한다.

## 남은 결정과 재조사 항목

- 대화·결과·엔딩의 최신 동작과 합의된 시간 정책 대조, 개별 전환 정책, 키 반복 수치, 최대 콘텐츠 너비·폰트·공통 색상 등의 실제 값.
- 테이블화할 항목과 레거시 이관 범위, 실제 화면 분할·프리팹 참조 구조·공통 요청 형식.
- D01~D09의 동작 결정은 완료했다. 실제 코드·씬 이관, 전체 화면의 추가 차이 발견과 기능 보존 대응표 작성은 P0 및 후속 구현 작업으로 남아 있다.

기능 가족 목록·현재 경로·담당은 [P0 현황](UIRefactorP0/Overview.md)에 등록했다. 각 기능의 상세 분기·전체 직렬화 연결·플레이 확인은 후속 이관에서 채운다. 등록 목록만으로 기능 보존 전수 확인 완료를 표시하지 않는다.
