# P2-C 연속 배치 비용 안내·D06

연속 설치 경로의 비용 부족을 단일 설치와 같은 대출 안내 흐름에 연결하는 단위다. 에디터 전체 MVP·저작 프리팹 전환이나 가격/지갑 모델 교체는 포함하지 않는다.

## 처리 경계

| 릴리스 때 재검사 결과 | 처리 |
| --- | --- |
| 경로·출력·해금·튜토리얼 조건 오류 | 기존 오류 안내, 경로 취소, 대출 제안 없음 |
| 부품 부족(달러도 부족한 경우 포함) | 부품 부족 안내, 경로 취소, 대출 제안 없음 |
| 부품 충족·달러 부족·대출 가능 | 경로를 먼저 취소하고 기존 대출 확인창 표시 |
| 부품 충족·달러 부족·대출 불가 | 경로 취소 후 해당 이유 안내 |
| 조건·비용 충족 | 기존 연속 설치 트랜잭션·일괄 결제·Undo 1건 |
| 움직이지 않은 클릭 | 기존 단일 설치 경로 유지 |
| 연속 삭제 | 기존 대상 재검사·일괄 삭제·환불·Undo 유지 |

대출 승인은 기존 지갑의 대출만 실행한다. 취소한 경로를 저장하거나 다시 재생하지 않으며 사용자가 직접 다시 배치한다. 기존 $3,000 대출·이자·하루 1회 제한과 튜토리얼 대출 안내의 Suspend/loan-taken 신호를 유지한다.

구조 실패와 자금 실패는 표시 문자열을 비교해 구별하지 않는다. 경로 일부가 만들어졌다는 사실만으로 대출 가능하다고 판단하지 않는다. 실제 팝업 표시는 기존 FeedbackUI를 사용하고 표시 실패를 승인으로 취급하지 않는다.

## 스트로크 생명주기

지난 D02의 정리 공백 지적은 호출 추적 결과 정정했다. CubeBuilder.OnDisable/OnApplicationFocus(false) → CancelPreview → CancelStroke가 기존에 연결돼 있다. 액션 비활성화가 canceled를 보내기 전에 경로·이벤트 구독이 정리되므로 중복 호출을 추가하지 않는다. 이 취소 경로는 설치·삭제·결제·환불을 실행하지 않는다. D01의 ESC 취소와 D02의 입력 점유는 유지한다.

## 통합 상태

WorkshopPlacementPlan.FailureReason으로 실패 종류를 구분하고, UpdatePlanarStroke의 릴리스 실패 분기에서 CancelStroke 후 TryOfferPlacementLoan을 호출한다. 이 함수는 단일 설치도 공유하며, 기존 대출 금액 상수·이자·선택창·튜토리얼 안내를 사용한다. 지갑 비활성·날짜 부재/무효·하루 제한·지갑의 대출 불가 조건과 팝업 표시 실패에는 이유를 반환한다. 연속 배치는 그 이유를 알리고, 기존 단일 설치의 일반 동작은 유지한다.

소스 대조에서 CommitStroke·CommitDeleteStroke·ExtendStroke와 단일 설치의 성공 구매 본문은 작업 시작 소스와 동일하다. OnDisable/OnApplicationFocus도 변경하지 않았다. 수정 스크립트3개를 AssetDatabase.ImportAsset으로 각각 임포트했다. 테스트·플레이·빌드는 실행하지 않았다. 기존 변경과 스테이징을 보존하고 실제 커밋은 만들지 않는다.
