# P2 메뉴·설정·편집 UI 병렬 이관

목표는 기존 화면에서 버튼·표시·게임 처리가 섞인 부분을 읽기 쉬운 MVP로 분리하고 실제 프리팹까지 연결하는 것이다. 전체 UI 이관 완료와 구분한다. 기존 D01/D02/D06, 슬롯 드롭·교환, 도메인의 결제·저장·카메라 규칙은 보존한다.

## 작업 경계

| 영역 | 기존 진입점 | 이관 범위 |
| --- | --- | --- |
| 시작 메뉴 | Start_UI | 새 게임·이어하기·불러오기·종료의 요청과 표시 분리 |
| 사운드 설정 | SoundSettingsUI | 음량·음소거·곡 선택·잠금/재생 상태·닫기/포커스 복원 |
| 무기 이름 | WeaponNameUI | 편집값과 실제 이름 구분, 저장·취소·대상 교체·튜토리얼 신호 |
| 레시피 | WeaponRecipeUI | 테이블 표시 가공과 기존 인라인 패널·스크롤 레이아웃 분리 |
| 층 이동 | WorkshopPlanarLayerUI | 주변 층·개수·선택 표시와 변경 요청 분리, D09 기존 버튼 복원 |
| 시점 조작 UI | WorkshopViewUI | 시점/축 메뉴와 축 그래픽·클릭 영역 표시, 도메인 요청 분리 |
| 일시정지 나가기 | PauseMenuNavigation | 기존 Feedback 확인창 재사용, 확인·중복 이탈 정책을 PauseExitPresenter로 분리 |

각 기존 MonoBehaviour는 외부 공개 API와 직렬화 참조를 보존하는 연결점으로 남는다. 구체적인 View는 프리팹에 저작하며 버튼/포인터 요청을 Action으로 전달한다. 일반 C# Presenter는 필요한 기존 도메인에서 상태를 읽고 요청한다. 지갑·저장·카메라 상태의 두 번째 원본을 만들지 않는다.

씬에서 기존 필드를 오버라이드한 경우에도 실효 참조를 보존한다. 새 View 컴포넌트가 기본 프리팹의 값만 읽어 씬 오버라이드를 무시하지 않도록 연결한다. 초기화는 기존 연결점이나 UIManager에서 먼저 호출해도 안전해야 하며 나중의 Awake가 표시 상태를 다시 숨기지 않는다.

## D09와 방향키

기존 층 버튼 8개를 사용한다. 윗줄은 이전/코어/다음, 아랫줄은 주변 5층이다. 각 줄의 좌우 이동과 줄 사이의 상하 이동은 Explicit Navigation으로 저작하고 끝에서 순환하지 않는다. Ctrl+휠도 유지한다. 슬롯 드래그 중에는 D02의 CanChangeView 조건으로 버튼 실행과 상태를 차단한다.

## 통합 상태와 한계

동시 워커 최대 8개로 구현·독립 검토·잔여 동적 UI 조사를 진행하고 완료된 슬롯을 나가기 흐름 분리와 추가 정적 검토에 재사용했다. 모델은 Qoder DeepSeek-Flash, Pi zai/glm-5.3-flash, Pi dgx-spark/qwen3.8-flash-next를 사용했다. 관리자는 현재 세션이다.

위 7개 진입점을 분리했다. UIManager에 View 5개, StartUI_Manager에 View 1개를 저작하고 기존 브리지의 m_view로 연결했다. 나가기는 기존 Feedback View를 사용하므로 새 컴포넌트가 없다. 브리지의 기존 참조와 씬 오버라이드는 유지하고 Initialize 전에 실효 참조를 View로 전달한다. 기존 persistent 버튼 호출을 유지한 시작 메뉴에는 중복 onClick 리스너를 추가하지 않았다.

Main의 층 버튼 비활성 오버라이드 8개를 해제하고 층 패널의 세로 공간을 복원했다. 모드/축 메뉴에서 층 버튼으로 들어가는 방향키 경로와 비순환 두 줄 탐색을 프리팹에 저작했다. 새로 표시될 때만 유효한 기존 선택을 보존하면서 코어 버튼을 기본 선택한다. D02 드래그 차단 중에는 기본 선택도 실행하지 않는다.

정적 대조에서 새 컴포넌트의 직렬화 필드·로컬 참조·GUID 중복 여부, 기존 오브젝트 ID와 persistent 호출 보존, Main의 수정 오버라이드 9개를 확인했다. 시작 메뉴 초기화의 재진입, View Awake 순서, 비활성 브리지의 프레임 갱신과 이벤트 해제 문제도 통합 중 보정했다. 수정 Assets 25개(기존 스크립트7·신규 스크립트15·프리팹2·씬1)를 각각 ImportAsset으로 임포트했고 전체 Refresh는 사용하지 않았다. 테스트·플레이·빌드는 요청받지 않아 실행하지 않았다. 기존 사용자 변경과 스테이징을 보존하며 커밋은 만들지 않는다.

현재 UIManager/StartUI_Manager/정산의 CanvasScaler 기준이 서로 다르고, 중앙 최대 너비와 저장 카드의 자동/수동 배치 충돌이 남아 있다. 이번 단위에서 스케일러를 일괄 변경하지 않았다. 위 항목은 소스 조사로 찾은 후속 작업이며 전체 화면 대조·플레이 보존 확인이 끝났다는 의미가 아니다. 사용하지 않는 중복 프리팹을 임의로 활성화하거나 삭제하지 않는다.

독립 보존 검토에서는 이번 이관의 구체적인 기능 누락을 찾지 못했다. 축 버튼·축 메뉴의 12버튼과 이름 저장·레시피 버튼은 기존 Automatic Navigation이 남아 있어 전체 입력 통합 때 명시 탐색으로 바꾼다. 이름·레시피·시점 화면의 기본 선택/복귀도 후속 범위다. 이 부분을 이번 층 버튼·시작 메뉴의 Explicit Navigation 적용과 혼동하지 않는다. 기존 브리지 참조를 실행 시 원본으로 쓰므로, 호환 이관이 끝나기 전에는 새 View의 중복 참조만 수정하지 않는다.
