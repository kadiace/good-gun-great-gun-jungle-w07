# 무기 공방 — 에이전트 메모
- 야간 습격 입장 차단 팝업은 확인 버튼을 카드 중앙에 배치하고, UIManager 캔버스는 1920×1080 기준 CanvasScaler로 4K 등 고해상도에서도 비율에 맞춰 확대한다. 확인 시 팝업만 닫혀 이전 지도가 유지된다.
- 무기별 시험 통과: EquipableWeapon.cs에 통과 ID와 구성 키를 런타임 보관(partial 분리 없이 통합). WeaponShareCode의 구성 수집을 재사용하며 이름·선택색·결제값은 키에서 제외한다. 모듈 설치/삭제/방향/구성 변경 시 즉시 전체 폐기, 되돌리기로 되살리지 않음. 총 이동·장착·거치와 도색은 통과 기록 유지. 저장 v6은 무기별 기록을 일반 저장·습격 왕복에 복원하고 이전 v2~v5는 미인증으로 읽는다. 프리셋/공유 코드/새 총에는 인증을 복사하지 않는다. 성능 데이터 자체를 조정한 경우 기존 통과 기록의 자동 버전 무효화는 미구현.
- 시험 요청 ID: shooting-test/behind-barrier, shooting-test/wide-targets, shooting-test/around-cover. 주문 표 손님 행 requestIds 또는 손님 풀 requests에 지정 가능(일회성 이관 메뉴는 제거). 시험 실패 후 F는 손에 든 총으로 재시도하며, 손이 비었거나 다른 상호작용을 보고 있으면 기존 줍기/작업대 입력을 우선한다.
- 손님 요청 목록(CustomerRequirementsUI)은 UIManager/QuestInfoPanel/Text_QuestDesc의 VerticalLayoutGroup 아래 조건별 행으로 표시(20pt 고정·자동 축소 없음, 충족 표시 칸과 줄바꿈 본문 분리, 현재 값은 다음 줄). NPC 조건 문구에는 한 방향/한 발사 경로 등의 범위 접두어를 생략하며 판정 규칙은 유지한다. 주문을 들은 현재 손님이 있을 때 표시하고 빈손에도 목록·미충족 상태 유지. 작업대 편집 중에는 작업대 총, 그 외에는 장착 총을 비교. 튜토리얼 목표는 별도 ObjectiveText 자식으로 분리. UI·태그·판매 판정은 CustomerRequestInfo 공유, NPC requiredTestIds도 표시·판정에 반영. 2/4방향 분할 모듈은 실제 발사 경로 전체의 고유 모듈 수를 합산(공유 모듈 중복·막힌 경로 제외), 서로 다른 경로에 설치해도 인정.
- 손님 저장 v6(v5의 요청 ID 형식 유지): 고정 손님 profileId와 선택 requestIds, 생성 주문 requestIds를 저장하고 정의는 TableManager에서 조회. 주문 ID가 비어 있는 이전 저장은 복원 시 새 ID를 발급하고, 형식이 잘못된 비어 있지 않은 ID는 거부한다. v2~v4의 일차/슬롯·조합 후보 인덱스는 읽기 호환만 유지(legacySlots가 이전 인덱스와 ID 연결). 기존 요청 에셋의 일회 이관은 Tools/Weapon Workshop/Migrate NPC Request Table이며 정상 플레이 중 표를 자동 생성하지 않는다.

- 시간제한 사격 프로토타입: TargetBell 기존 무제한/커스텀 소환 유지, 별도3종(장애물 뒤·넓게 흩어진·엄폐 뒤) 선택. Resources/ShootingTestTableData.json → ShootingTestTableData → TableManager.ShootingTestTable → ShootingTestInfo에 이름·시간·파괴율·힌트, Data/ShootingTests SO는 시험 ID/배치 프리팹 참조 어댑터만 유지, Prefabs/Range/ShootingTests에 개별 편집 배치. 임시 기본30초·초록 목표별70% 파괴, 붉은 보호 표적 일부 파괴 시 즉시 실패. ShootingRange/TimedTestPoint 생성·HUD 시간/파괴율/비전방 총구 경고(로컬 방향, 경고만). 실패 시 회차 표적·사용 총의 남은 공격 정리·타이머 초기화, 테이블3m 안에서 기존 F로 시선 없이 재시도(PlayerShootingTest), 실패 화면 Esc 종료. 성공 즉시 종료·4초 후 HUD 숨김. scaled time·시작 숨김, 밤/재시작/불러오기/비활성화 취소. 시험 배치·진행은 저장 제외. 시험 중 장착 총 변경/해제·모듈 변경 시 즉시 실패하여 재시도 가능. 시험 토큰·공격별 파괴 출처 추적은 적용하지 않으며 다른 총의 이전 지연 공격까지 완전히 차단하지는 않는다. 플레이 미확인.
- 폭발 복셀 후보는 원본 메시 범위 밖이면 최초 분할을 생략하고, 범위 내 격자만 조회한 뒤 기존 거리·방향·거리층과 셀 순서로 판정한다. 활성 폭발 파동의 복셀 변경은 초기 Update 단계에서 각자 즉시 반영하고, PoolManager가 일반 Update 물리 조회 전에 대상별 콜라이더를 한 번 재구축·동기화한다. 배치보다 이른 탄환 물리 조회는 조회 직전 동기화하고, 늦게 갱신된 폭발과 관통 충돌 갱신은 즉시 처리한다.
- NightRaid 폴더의 배치된 DestructibleTarget 셀 ID는 `씬 이름/직렬화된 TargetId/X_Y_Z`(0부터 시작하는 원본 메시 격자 좌표). `DestructibleTarget.TryGetCellId(Vector3Int, out string)`으로 붙어 있는 셀을 제거하기 전에 조회한다. ID는 대상의 이름·계층·생성 순서와 무관하며 씬 파일에 보존된다. 메시 경계·크기·Part Size를 바꾸면 같은 좌표가 다른 공간을 가리킬 수 있으므로 기존 ID의 공간적 의미를 유지하려면 격자 정의를 보존하거나 별도 이관해야 한다. `Assets/Editor/RaidBlockIdentityEditor.cs`의 Tools/Weapon Workshop/Block IDs 메뉴에서 누락 ID만 발급(대상에 기존 WorldSaveIdentity가 있으면 그 값을 우선 사용)·전체 8개 씬 검증; 기존 ID 중복은 자동 교체하지 않고 오류로 보고하며 빌드 전에도 검사한다. 배치 대상 20,465개 누락·중복 0건 확인. 런타임에 생성되는 상자·적 프리팹은 씬 배치 대상이 아니므로 별도의 영구 ID를 보장하지 않는다.
- 시각 파편은 주 카메라 6m 안쪽에서는 기존 이동·충돌·표시를 유지한다. 바깥에서는 격프레임 단순 이동(벽 검사·회전 생략), 안정된 파편별 표본 선택과 구름별 최대 256개 표시를 적용한다. 수명·원래 복셀 파괴·연결 낙하 덩어리는 제한하지 않는다. 카메라가 없으면 원래 동작을 유지한다.
- ProjectileTest의 화면 내 임시 표적에서 폭발 11·샷건 1 총구 발사 A/B: GPU 프레임은 대체로 1ms 내외로 병목이 아니었고, 정상 명중 시 두 경로 모두 폭발 3회·복셀 1062~1063개 제거. 예열된 Editor 표본에서 파편 CPU 최대 약 9~10ms→0.6~0.7ms, 폭발 이후 CPU 프레임 P95 약 8.7~12.5ms→2.8~3.1ms. 실제 플레이어 화면/빌드 GPU와 파편 시각 품질은 별도 확인 필요.

- 저장소 구조: 씬은 `Assets/Scenes/Intro`(메인메뉴·StartUI_Manager), `Assets/Scenes/Main`(공방·사격장), `Assets/Scenes/NightRaid`(습격·튜토리얼), `Assets/Scenes/Test`(시험). 씬 이름 문자열(`LoadSceneAsync`, `mainMenuScene`, `gameSceneName`, `standaloneWorkshopScene`, 에디터 스크립트 경로)는 실재 이름 Intro·Main과 NightRaid 폴더로 통일했다.
- 자산 배치: 에디터 전용 도구는 `Assets/Editor`(플레이어 빌드에서 제외되어야 하므로 `Assets/Scripts`에 두지 않는다). `Prefabs` 루트는 `Player`·`Workbench`·`Range`·`Shop`·`NightRaid`로 나누고, NightRaid 출구 재질은 `Materials/NightRaid`, 출구 심볼 메시는 `Meshes/NightRaid`, 입력 액션 참조는 `Data/Input`, 배경 이미지는 `Textures/Backgrounds`에 둔다. URP 템플릿 잔재(`TutorialInfo`, `Readme.asset`, `Assets/Temp`)는 제거했다.
- 경로 제약: `Resources/Sound/BGM|SFX`(SoundManager), `Resources/Stickers`·`Resources/Keyrings`(ModulePaletteUI), `Resources/RaidMapData.json`, `Prefabs/Managers/Resources/PoolManager.prefab`(PoolManager), `Assets/InputSystem_Actions.inputactions`(루트 유지)는 코드에 경로가 박혀 있어 옮길 때는 해당 로더와 에디터 스크립트의 경로를 함께 바꾼다. 프리팹/씬 참조는 `.meta`와 함께 이동하면 GUID가 보존된다.
- 동적 TMP 폰트 에셋(Clear Dynamic Data On Build 켜짐)은 Editor/DynamicFontAssetSaveCleaner가 저장 직전 글리프·아틀라스를 비워 플레이로 채워진 데이터가 변경점으로 남지 않게 함. 폰트 에셋에 변경점이 뜨면 생성 데이터이므로 되돌리면 된다.
- `Assets/Scripts`는 공용 파일이 루트에 많고 기능별 폴더 분리는 아직 미완이다(분리 시 `namespace WeaponWorkshop`이므로 이동만으로는 참조가 깨지지 않는다).
- 테이블 정례: 참조 테이블은 `Resources/X.json`(데이터) → `XData`(직렬화된 필드만 둔 순수 자료, 메서드 두지 않음) → `TableManager`(한 번 로드해 인스턴스로 보유) 3층으로 만들고, 조회와 문구 생성은 별도 정적 클래스(`XInfo`)의 확장 메서드로 둔다. `TableManager`는 MonoBehaviour·스크립터블오브젝트·씬 연결 없이 `BeforeSceneLoad`에 초기화하고 `SubsystemRegistration`에서 정적 잔재를 정리한다. 프로퍼티명은 클래스명에서 Data를 뺀 이름(`RaidMapData` → `TableManager.Instance.RaidMap`)을 쓰고, 로드 실패는 빈 표와 오류 로그 1회로 처리하며 조회는 null 안전해야 한다. 습격 스테이지와 손님 요청·태그 정의에 적용했다.
- 테이블 적용 현황: 습격 스테이지는 RaidMapData, 손님 요청·태그 정의는 `Resources/CustomerRequestData.json` → `CustomerRequestData` → `TableManager.CustomerRequest` → `CustomerRequestInfo`. 요청 행은 무기 조건만 담는다(중복 복사 행 52→27로 병합, 옛 ID·GUID는 legacyIds/legacySlots로 유지해 이전 저장 파일 호환). 조건 measure/stat은 enum 이름 문자열로 적고 로드 때 해석하며, 상한 없음은 max 생략. requiredModules는 조건에서 계산되므로 제거. 주문은 `Resources/CustomerOrderData.json` → `CustomerOrderData` → `TableManager.CustomerOrder` → `CustomerOrderInfo`: sale(태그 보너스 비율 0.5·불만족 비율 0.8), pools(손님 풀: 후보 요청별 unlockDay·excludes, 요청 수, 기본가·요청당 가격, 대사 틀), days(일차별 자리세·조합 손님 설정), guests(손님 SO profileId 키: 요청·판매 보너스 예외 noBonusRequestIds/bonusRequestIds·보상·대사·unlockDay). CustomerProfile·CustomerDay·CustomerRequestPool SO에는 에셋 연결(프리팹·초상화·안내·코어 기본 스탯)과 일차 손님 순서만 남기고 값은 표에서 읽으며, 무한 모드·저장 복원 손님/일차는 런타임 값을 쓴다(Instantiate 시 CopyRuntime*로 복사). 고정 손님 등장 제한은 손님 행 unlockDay(D4_9_Snaiper=5, 기존 유도 요청 unlockDay 유지분)만 본다. 불만족 판매가는 제작비×0.8 반올림(기존 cost/5*4와 5의 배수 제작비에서 동일). 사격 테스트 정의도 ShootingTestTableData에 이관했고 기존 SO에는 ID와 배치 프리팹 참조만 남겼다. 레거시로 남은 모듈 사양·가격·해금 카탈로그(순서+1 ID), 손님 외형(프리팹·초상화)·일차 손님 순서·튜토리얼 시퀀스는 에셋 참조라 SO에 남겼다. 레시피는 태그 ID로 TableManager.CustomerRequest를 직접 조회한다. 기존 태그 에셋 참조는 정의를 복제하지 않는 ID 어댑터로 유지한다. 효과음·장식·풀 경로 로더도 미이관.
- 레거시 표시: ModuleCatalog·ShopCatalog·GunArchetype·WeaponTypeData·ShootingTestData 및 이전 요청 필드는 `[Obsolete]`로 TableManager 사용을 안내한다. CS0618은 승격 점검 목록으로 유지하며, 이관 에디터 브리지만 파일 상단 pragma로 숨긴다. 외부 호출 없는 기존 경로 로더에는 `레거시 테이블:` 주석을 유지한다.
