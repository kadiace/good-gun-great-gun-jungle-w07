# 산탄 폭발 랙 수정 보고서

## 원인

- 원인은 **산탄 분열과 폭발 연쇄 기폭의 조합**이다. `ProjectileStatsSource.cs:321-323`에서 산탄 점수 n을 `(2n+1)²`개 펠릿으로 만들고, `ProjectileStatsSource.cs:351-353`에서 나머지 탄을 추가 대여한다. 산탄 구성은 폭발력을 절반으로 낮추지만(`ProjectileStatsSource.cs:179-185`), 펠릿별 폭발 호출은 그대로 생긴다.
- 각 폭발의 `Step`은 활성 발사체 전체를 순회해 반경에 든 탄을 기폭한다(`ExpandingExplosion.cs:304-314`). 기폭은 정지 영역 효과를 적용하고(`ProjectileMotor.cs:100-110`, `ProjectileEffects.cs:43-51`), 다시 `HitPayload`에서 `ExpandingExplosion.Create`를 호출한다(`HitPayload.cs:27-35, 47-55`). 따라서 산탄의 초기 분열이 폭발 수를 늘리고, 활성 파동들이 그 탄을 다시 기폭하는 피드백 경로가 함께 존재한다.
- 프로파일러 프레임 1208에서 `Create` 446회/253.88ms, `CollectPieces` 446회/167.06ms, `Step` 1,071회/33.18ms였다. Create·CollectPieces 항목의 할당 합은 약 88.4 MB다. `Instantiate.Copy`는 프레임 1208에 529회, 1207에 1,642회, 564에 2,244회였다. 당시 PoolManager 설정은 폭발 파동 프리웜 32개·보관 128개였고, FX_Explosion 풀은 프리웜 64개였다(`Assets/Prefabs/Managers/Resources/PoolManager.prefab:54,69-71`). 코드 경로와 이 수치는 산탄 분열·연쇄 및 프리웜 부족이 맞물린 상황과 일치한다. 제공된 프로파일러 요약만으로 각 분기별 기여 비율은 분리할 수 없다.

## 변경 요약

- `ExpandingExplosion.cs`: 같은 프레임 요청을 모아 병합 후 파동을 만든다. 파편 수집용 타깃·체력·Piece·그룹 컬렉션, 활성 발사체 버퍼, 파손 대상 집합을 정적 공유 버퍼로 바꾸고, 재사용 레이어 캐시를 전체 8,192개로 제한했다. 기존 Create/CollectPieces/Step 마커를 유지하고 Merge·Build 마커를 추가했다.
- `PoolManager.cs`: 연쇄 기폭 상한과 FX 상한을 인스펙터에 추가했다. 기본은 각각 64회/프레임과 32회/프레임이다. 폭발 파동 풀은 기존 직렬화 값이 작더라도 최소 256개를 프리웜·보관하고, FX 풀은 최소 128개를 확보한다. 프레임 상한을 넘긴 연쇄 후보는 다음 프레임에 처리하며, ClearActive/매니저 파괴 때 대기 요청을 비운다.
- `ProjectileMotor.cs`: 지연 처리되는 연쇄 기폭도 감지 당시 위치·방향을 사용하도록 오버로드를 추가했다.
- `ProjectileStatsSource.cs`: 활성화 시 폭발 FX 풀 최소 프리웜을 확보한다.
- `README.md`: 병합과 예산 규칙을 현재 상태 메모에 추가했다.

## 병합·상한 규칙

- 같은 프레임에 `WeaponSource`가 같은 비-null 무기에서 생긴 폭발 중 두 반경의 작은 값의 절반 이내에 중심이 있으면 한 요청으로 합친다. 중심은 먼저 들어온 폭발의 위치를 유지한다.
- 위력은 요청 위력 합을 가장 강한 요청의 4배에서 제한한다. 반경은 기존 요청 중 최댓값과 누적 위력의 세제곱근으로 계산한 반경 중 큰 값으로 한다. 이로써 병합 폭발의 피해·파괴 에너지를 제한된 합으로 보존한다.
- PoolManager 인스펙터에서 연쇄 기폭 64회/프레임, 폭발 FX 32회/프레임을 조절한다. 초과 연쇄 후보는 삭제하지 않고 대기시키며, FX 예산 초과는 연출만 생략한다. 폭발 파동/FX 풀의 최소 예열량은 256/128개다.

## 동작 변경

- 병합되지 않은 단일 폭발의 입력 위력·반경·피해·파괴 판정은 기존과 같다. 병합된 다중 폭발은 한 파동과 FX 하나가 되며, 피해·반경은 위 제한 규칙을 따른다.
- 연쇄 기폭 상한을 넘은 탄은 후속 프레임에서 감지 당시 지점에 폭발을 만든다. 프레임 상한 초과 시 FX는 표시하지 않아도 피해 판정에는 영향이 없다.
- 병합을 위해 요청은 `PoolManager.LateUpdate`에서 파동으로 확정한다. 일반 Update 중 생성된 파동은 기존처럼 다음 Update부터 진행하지만, FixedUpdate 등 이른 단계에서 만든 파동은 시작이 프레임 끝까지 미뤄질 수 있다.

## 남은 위험과 확인

- 서로 떨어진 직접 폭발은 공간 병합 대상이 아니므로 한 프레임에 256개를 넘는 동시 파동이 생기면 풀 확장 Instantiate가 다시 발생할 수 있다.
- 복셀 파손 자체의 비용은 남는다. 기존 보고서에서 `DestructibleTarget.UpdateCollisionRuns`는 45.22ms였고 `ParticleSystem.GeometryJob`은 다른 스파이크에서 247.78ms였다. 이 수치가 병합 후 얼마나 줄었는지는 이번 작업에서 플레이·프로파일링하지 않았다.
- 수정 Assets 네 파일에 `AssetDatabase.ImportAsset`을 실행했고, `unity --no-banner recompile --timeout 180`은 출력 없이 종료 코드 0으로 끝났다. 플레이와 테스트는 실행하지 않았다.
