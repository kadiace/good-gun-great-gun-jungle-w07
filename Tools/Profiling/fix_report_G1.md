- `last_report.txt:73`의 `GameObject.AddComponent`는 2,383회지만 프로파일 요약에 호출 스택 분해는 없다. 표적 코드의 충돌 열 경로에서는 `BoxCollider`가 추가되던 것이 원인이었다. 현재 표적 코드의 AddComponent 지점은 `DestructibleTarget.cs:1097`이며, 열 갱신은 사전 확보된 풀에서 받는다(`:1170`). 다른 시스템의 AddComponent 호출까지 이 수치에 포함됐을 수 있다.

## 파일별 변경

- `DestructibleTarget.Rendering.cs`: 유효한 지지 상태에서는 바닥 접촉 칸을 제거했더라도 제거 경계의 연결 성분만 재판정한다. 각 성분에 남은 바닥 접촉 셀 또는 외부 지지 셀이 있는지 확인하고, 둘 다 없을 때만 그 성분을 떨어뜨린다. `ResolveSupport.Local` 및 `FullFallback` 마커는 유지했다.
- `DestructibleTarget.cs`: 셀 구조체의 불필요한 초기 위치·초기 크기·회전·인덱스 필드를 제거해 요소 데이터 필드를 약 92B에서 48B로 줄였다(런타임 정렬에 따른 배열 stride는 미측정). 초기 위치와 크기는 `ResetTarget`에서 격자 값으로 복원한다. 콜라이더 풀을 표적별로 준비하고, 최대 수직 런 수(`X × Y × ceil(Z/2)`)까지 Awake/사용자 크기 설정 중 확보한다. 런이 늘 때 풀의 콜라이더를 재사용하고 사용하지 않는 것은 `enabled`를 끈다.
- `DestructibleTarget.StructuralSupport.cs`: 인접 표적의 외부 지지 상태가 바뀌면 캐시를 무효화하는 대신 현재 셀을 재판정 경계에 모두 넣는다. `StructuralSupportGraph.cs`는 수정하지 않았다.

## 동작 변화와 동등성 근거

- 연결 규칙과 지지 조건은 기존 전체 판정과 같다. 전체 판정은 바닥 또는 외부 지지가 있는 셀에서 인접 셀로 Flood한다. 따라서 같은 연결 성분은 지지 셀이 하나라도 있으면 전부 유지되고, 하나도 없으면 전부 낙하한다. 유효한 이전 상태에서 삭제로 새로 분리되거나 지지를 잃은 성분은 반드시 삭제 셀의 생존 이웃 경계에 닿으므로, 그 성분만 탐색해도 떨어질 셀 집합이 같다. 바닥 셀 삭제는 남은 성분에서 바닥 지지를 다시 확인한다.
- Reset 후 이전 지지 상태가 유효하면 모든 셀을 경계로 넣어 각 성분을 재판정한다. 이웃 지지 변경도 아래쪽 지지 조건에 해당하는 표적의 모든 셀을 경계에 넣는다. 비활성화 시 연결 정보가 사라질 수 있어 지지 상태를 무효화한다.
- `FullFallback`은 최초 지지 판정 등 유효한 과거 지지 상태가 없는 경우에 남는다. 재활성화 뒤 다음 판정도 연결 그래프가 다시 구성될 때까지 이 경로를 쓴다. 이동체 부착 표적은 기존처럼 구조 지지 계산에서 제외된다.

## 인스펙터 값 및 남은 위험

- 새 인스펙터 항목은 없다. 콜라이더 풀 크기는 격자 크기로 계산하며 기존 `Part Size` 설정을 사용한다.
- 최대 분할 런 수만큼 비활성 BoxCollider를 미리 만들므로 씬 초기화 시 컴포넌트 수와 시간이 늘 수 있다. 표적 크기가 런타임에 증가하면 `Subdivide`에서 풀을 보충한다. 게임 플레이 프로파일은 다시 측정하지 않아 폭발 프레임 할당·시간 감소량은 아직 확인되지 않았다.
- 수정한 Assets 파일은 `AssetDatabase.ImportAsset`으로 임포트했다. `unity --no-banner recompile --timeout 180`은 출력 없이 종료 코드 0이었다. 지침에 따라 플레이와 테스트는 실행하지 않았다.

## README 제안

- 유효한 지지 상태에서 셀 파괴는 제거 경계 연결 성분만 재판정하며, 최초 판정이나 상태 무효화 뒤에는 전체 판정을 수행한다.
- 셀 데이터는 평탄 배열에 저장하고, 표적의 충돌 열은 사전 확보한 BoxCollider 풀을 재사용한다.
